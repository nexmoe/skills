# i18n 与多语言最佳实践

**1** **横幅什么时候显示？** 只挂在营销页面 Header 上方，浏览器加载后显示。条件是：浏览器首个受支持语言与页面语言不同、当前页提供该语言版本、用户未关闭过该语言建议。**不检查 Cookie 或此前的手动语言选择。**

**2** **横幅有什么内容和按钮？** 语言图标、提示文字、带箭头的切换按钮、× 关闭按钮，没有国旗。**提示和按钮都使用推荐语言。** 推荐中文时是“检测到浏览器偏好使用中文。”和“使用中文浏览”。

**3** **点击横幅怎么跳转？** 点击后通过普通链接整页切换，不保存语言偏好或“已接受推荐”记录。**目前只取 pathname，会丢查询参数和锚点。** 点击 × 则隐藏并保存关闭记录，不跳转。

**4** **Footer 怎么切换？** 展开语言菜单，列出所有网站支持的语言，但是如果当前页面没有相关对应语言的内容，就直接禁用该对应语言；可选语言不足两个时隐藏。不保存语言 Cookie，也不写到账户。

**5** **下次重新进入是什么语言？** 只看本次打开的 URL：无前缀为英文，`/zh` 为中文，`/ja` 为日文。刷新中文地址仍是中文；重新打开首页 `/` 则是英文。**不会恢复上次选择，`NEXT_LOCALE` Cookie 也不参与页面语言判断。** `/en/...` 会 308 去掉英文前缀。

**6** **手动选择和浏览器偏好冲突时谁优先？** **页面显示由 URL 决定，横幅推荐仍由浏览器偏好决定。** 例如浏览器偏好中文，用户主动切到日文，日文页面上仍可能出现中文建议。手动选择不会抑制这个建议。

**7** **哪些选择会被记住？保存多久？** Web 不记住主动选择的语言。只记住“关闭某语言建议”，**按语言分别记录、整个站点生效、没有过期时间**。

**8** **没有对应翻译怎么办？** 内容页缺少目标语言但有英文时，通常 **307 到英文**；英文也不存在则 404。更新日志和法律页目前为英／中，比较详情的可选语言列表为英文，博客按已发布语言判断。横幅不推荐不可用的语言，也不会再尝试浏览器第二偏好的语言。部分功能页的可选列表默认按三语提供，实际缺失再由页面检查回退。

**9** **切换时保留哪些状态？** 选择后整页切换，**保留路径、查询参数和锚点**。

**10** **多语言 SEO 做到什么程度？** 已实现按页面语言生成标题、描述、canonical、hreflang、OpenGraph，以及多语言 sitemap；HTML `lang` 读取当前语言。内容页会根据实际翻译生成替代语言链接，`x-default` 指向英文。不过全站 WebSite 结构化数据的 `inLanguage` 仍固定为 `en`。
