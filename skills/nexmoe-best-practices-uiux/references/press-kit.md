# Press Kit 媒体素材包

目标是让记者、目录站、推荐者和内容创作者无需来回沟通，就能快速获得准确信息和可直接使用的素材。

## 公开入口

- 在产品官网提供固定公开页面 `/press-kit`；多语言版本沿用网站现有语言路由，例如 `/zh/press-kit`。
- 页面和素材无需登录、无需申请权限，任何人都能直接访问和下载。
- 网站页脚提供明确的“Press Kit”链接。

## 设计一致性

- Press Kit 页面必须符合网站整体设计风格，沿用现有页面布局、导航和页脚，以及字体、配色、间距、圆角和交互规范。
- 复用网站现有组件与设计令牌，让事实清单、素材预览和下载入口保持与其他页面一致的视觉层级及操作体验。

## 内容与素材

| 类别 | 必含内容 | 规格与注意事项 |
| --- | --- | --- |
| Fact Sheet（事实清单） | 产品名、一句话介绍、价格、平台、发布日期、开发者、官网 / 商店链接 | 放在页面最上方，以便直接复制。 |
| 文案 | 短介绍（1–2 句，可直接引用）和稍长介绍（2–3 段） | 使用准确、清晰的表述，避免过度营销话术。 |
| Logo / 图标 | 透明背景 PNG 和 SVG；提供彩色 / 单色、深色 / 浅色、横版 / 竖版等适用版本 | PNG 使用高分辨率，文件命名清晰。 |
| 截图 | 6–12 个场景的原始干净截图，按产品支持的语言分别提供 | 提供全分辨率 PNG，无水印、无营销文字、无设备框；可额外提供带框版本。不要只提供 App Store 带文案的截图，也不要用不同语言或主题的同一场景凑足数量。 |
| 联系方式 | 真实且有人监控的邮箱 | 优先提供人名和邮箱，不要只留联系表单。可以先问用户留什么邮箱|

截图、Logo / 图标及其他视觉素材在浅色（light）与深色（dark）模式下有区别时，必须展示两种版本，并分别提供下载。明确标注每个版本适用的模式，文件名使用 `light` / `dark` 区分，例如 `screenshot-dashboard-light.png`、`screenshot-dashboard-dark.png`。页面无论当前处于哪种主题，都应能查看和下载两种版本；透明 Logo 使用适合其用途的预览底色，确保可辨识。

按已有素材补充以下可选内容，不将其作为基础可用性的前提：

- 其他视觉：宣传图、Banner、社交分享图、Key Art，提供 16:9、1:1 等适合用途的比例。
- 视频 / Trailer 链接、创始人简介和头像、近期报道、品牌色值。

## 多语言内容与素材

- Press Kit 页面文案、素材说明和下载按钮跟随当前页面语言，遵循 [i18n 与多语言规范](i18n.md)。截图语言按产品实际支持的 locale 提供，不以官网页面语言推定产品支持的语言。
- 默认预览和下载与当前页面语言匹配的截图，同时提供明确的素材语言选择，让访问者能查看和下载其他语言版本。缺少匹配版本时标明实际素材语言，不把英文截图标成已本地化版本。
- 截图按“场景 × 产品支持的 locale × 有差异的 light / dark 主题”组织；每个语言版本覆盖相同场景，保持产品状态和业务含义一致。没有语言差异的 Logo 等素材可共用，不必为每种语言重复生成。
- 单张下载及打包下载保留语言和主题标识；按语言打包时明确范围，完整素材包按 locale 分目录，避免同名文件覆盖或混淆。

## 截图制作

- 可以在产品的本地或演示环境中 mock 贴近真实使用场景的数据，再用 Playwright 运行实际产品、操作界面并截图。
- 模拟数据必须合理可信，符合产品业务逻辑：名称和内容有实际含义，日期与状态一致，金额、数量、汇总及图表相互吻合。避免无意义占位符、随意堆砌数字或夸大使用成果。
- mock 数据中面向用户的名称、描述、示例正文、分类和图表标签等内容按 locale 组织，由截图所用语言选择对应数据；界面文案继续使用产品现有翻译资源，避免只翻译按钮而内容仍混用另一种语言。品牌名、专有名词等本就无需翻译的内容可保留原文。
- 各语言 mock 数据共用场景结构和业务关系，只将语言相关的内容与格式关联到 locale，避免复制出独立的业务逻辑。日期、数字和金额使用产品现有本地化格式；切换语言不擅自改变币种、金额或业务状态。
- 截图取自实际运行的产品界面；模拟数据应通过产品正常的数据渲染流程呈现，不制作脱离产品的仿制界面，也不通过修改 DOM 或后期拼图伪造功能与状态。
- 用 Playwright 逐个 locale 通过产品真实的语言路由、设置或语言入口进入界面，并加载同 locale 的 mock 数据；产品依赖浏览器语言时同步设置浏览器上下文。确认产品实际生效的语言后再截图，不通过后期替换文字生成其他语言版本。
- 用 Playwright 等待数据、字体和图片加载完成，确认界面稳定后输出全分辨率 PNG，并逐张检查内容、布局和清晰度。存在 light / dark 差异时，使用相同场景和数据分别截图，遵循前述双版本展示与下载要求。
- 按 locale 和主题逐张检查界面文案与 mock 内容的语言是否一致、日期和数字格式是否正确，以及长文本、字体缺字、换行和溢出问题；产品支持 RTL 语言时同时检查方向与布局。核对预览、单张下载和压缩包内文件的语言与标识一致。

## 维护与文件命名

- 重大版本更新、新功能或新增语言上线后，同步更新各语言的截图和描述，确保事实清单中的价格、平台和链接等信息准确。
- 文件名包含产品、用途或尺寸等可辨识信息；有语言差异的素材还须包含产品实际使用的 locale，并保留主题标识，例如 `screenshot-dashboard-zh-CN-light.png`、`screenshot-dashboard-en-dark.png`。无语言差异的素材可使用 `product-name-icon-1024.png`，避免使用 `image1.png`。
